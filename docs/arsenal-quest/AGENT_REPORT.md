# Arsenal Quest — Agent Implementation Report

Implements GitHub issue #1 per `docs/arsenal-quest/AGENT_HANDOFF.md` (authoritative).
Note on branch: the Arena session is pinned to `arena/01a0cf5e-apex-chaos`; that branch was
fast-forwarded onto `origin/prototype/arsenal-quest` (042352a) so it contains the full spec
verbatim, and all implementation work is layered on top. Nothing was pushed to
`prototype/arsenal-quest` itself.

## What was added (new files)

- `public/game/arsenal/arsenalQuestConfig.js` — all P0 tuning constants (spawn cadence 3.0s,
  reveal delay 1.2–1.8s, margin 90, pickup radius 42, 20s pickup lifetime, 8-slot soft cap,
  per-weapon numbers) + `[AQ]` structured logger + shared state holder.
- `public/game/arsenal/arsenalWeaponRuntime.js` — data-driven registry for exactly the 12 P0
  weapons (`window.APEX_ARSENAL_WEAPONS`), holder-state driver, damage pipeline (Tower Shield
  reduction point), aq_* projectile movement/hits, grenade throw/fuse/blast, swirl reflect with
  ownership swap, slash/aim/windup visuals, isolated aq projectile renderer.
- `public/game/arsenal/arsenalSpawnRuntime.js` — slot lifecycle TELEGRAPH→REVEALED→PICKED_UP→REMOVED,
  timer-driven cadence independent of collection, reveal rolled only at reveal time, soft-cap
  suppression logging, pickup resolution (first unarmed overlapping fighter; armed fighters are
  rejected and logged), isolated placeholder renderer (logical sprite keys per
  `P0_ASSET_MANIFEST.csv`; no silhouette design in code).
- `public/game/modes/arsenalQuestRuntime.js` — mode entry/exit, blank HERO/RIVAL FighterTypes
  (100 HP, `noRage`, no update/onCollide/onTakeDamage — pure Apex movement/bounce/collision),
  `gameState='ARSENAL'` update/draw/background/projectile wrappers (same convention as
  solo/trial/tamChien runtimes), F3 debug overlay, `window.getArsenalQuestDebugState()`,
  KO/rematch/exit handling, keyboard listener registered only while in mode.
- `tools/testArsenalQuestRuntime.mjs` — browser CDP acceptance tool (repo test conventions;
  needs a Chrome/binary + reachable browser CDN, unavailable in this sandbox).
- `tools/testArsenalQuestHeadless.mjs` — headless acceptance harness that runs the REAL engine +
  Arsenal runtimes inside jsdom with a real @napi-rs/canvas 2D context; deterministic stepping
  plus genuine PNG canvas renders.
- `docs/arsenal-quest/evidence/` — 10 PNG frames + `headless-test-report.json` (full gate data).

## Known defects / compromises

1. Session branch constraint (see header). Reviewer can fast-forward `prototype/arsenal-quest`
   onto this branch later if desired.
2. No browser exists in this sandbox (Chrome-for-Testing, Playwright CDN and Debian mirrors are
   all network-blocked), so acceptance screenshots are canvas renders from the headless harness,
   not full browser-page screenshots; the menu/React shell is not visible in them. The CDP tool
   is committed for browser-capable environments.
3. Placeholder presentation only (per §13): 3-letter discs + tags; no final weapon PNG/VFX/SFX
   integration (deferred by design).
4. Grenade detonates on fuse only (no direct-contact trigger); the lob aims near the target.
5. In the harness, `apexPickRuntime` (champion-select UI, unrelated to this mode) parks on a
   stubbed fetch; it loads normally in a real browser.
6. Five-minute headless sim uses deterministic 30Hz stepping of the shared simulation tick, not
   wall-clock rAF; the rAF loop itself is exercised by normal-mode launch + redraw paths.

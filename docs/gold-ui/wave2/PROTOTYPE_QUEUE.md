# APEX CHAOS — Wave 2 Gold Visual Prototype Queue

This queue is deliberately independent from the active Wave 1 implementation.

Recommended order is based on dependency clarity and risk, not implementation urgency.

## 1. Settings
Why first:
- smallest surface;
- validates shared Gold material language without creating another world;
- locks overlay grammar, form controls and accessibility presentation;
- tests the global audio/effects vocabulary.

## 2. Dictionary / Combat Archive
Why:
- read-only;
- no economy mutation;
- can reuse current hero/weapon art;
- tests information-heavy Gold UI without card-dashboard drift.

## 3. Profile / Account
Why:
- locks player record / save-security language before cloud implementation;
- establishes quiet personal-data visual grammar;
- tests DEVICE SAVE / SECURED states.

## 4. Fighter Shop / Registry
Why:
- needs the strongest contrast with Lucky Draw;
- must wait until Profile/economy boundary is visually understood;
- transaction states need careful review.

## 5. Missions / Operations
Why:
- can reuse the information grammar learned from Dictionary while remaining objective-driven;
- must not become a live-service checklist.

## 6. Upgrade / Calibration
Why last among designed surfaces:
- product philosophy is locked but content is intentionally limited;
- Story augments must remain absent until Story encounter needs exist;
- prototype must prove usefulness without inventing fake RPG systems.

## Result

Do **not** make a separate competing Result prototype by default.
Use the current Gold Battle result source and apply the semantic extension authority.

## Story

No prototype until data exists.

## Acceptance method for every new prototype

Before moving to the next surface:
1. desktop normal-scale review;
2. mobile landscape;
3. mobile portrait;
4. interactive states;
5. motion/noise self-critique;
6. cross-check against Wave 2 anti-drift;
7. owner acceptance;
8. pin source/hash.

Do not mass-generate seven mediocre screens in one pass.

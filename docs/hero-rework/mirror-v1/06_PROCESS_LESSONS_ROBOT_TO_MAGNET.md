# MIRROR PRELOAD — PROCESS LESSONS FROM ROBOT -> HUNTER -> CRYSTALA -> FROST -> MAGNET

This file is a distilled failure-prevention authority, not a history essay.

## 1. Global 12-Hero failure — green tests can protect the wrong product

The first broad rework could be internally consistent while owner playtest still failed because global locomotion and missing mechanics were not exercised honestly. Tests pinned bodies or disabled behavior they purported to protect.

**Mirror law:** every key behavior needs non-vacuous real-path evidence. Never treat a passing internal counter as proof of user-visible behavior.

## 2. Robot — coordinate ownership and choreography are not optional

Robot correction established:
- exact Gold/source identity matters;
- production must not reinterpret Gold orientation;
- local/world coordinate ownership must be explicit or effects/weapons detach;
- real equip/fire paths matter;
- gameplay can outrun authored visual choreography if transaction timing is not tied to Gold;
- generic renderer layers can contaminate a hero's identity.

**Mirror application:**
- A1 real equip waits for the Gold OWN edge;
- node collision and node art share the same transformed surface;
- A1 peel uses the actual weapon through Gold geometry;
- no generic circular portal remains underneath the Gold node.

## 3. Hunter — latest exact donor identity + immutable shared assets

Hunter V10 showed:
- canonical path + SHA beats stale labels/comments inside a prototype;
- a visual supersession can change only a renderer/state layer while mechanic mapping remains valid;
- multi-instance derived material should be generated once, mutable state per instance;
- do not restore an old global squash because an obsolete state field still exists.

**Mirror application:**
- Gold 12 path/hash define authority;
- old 9/10/13/14 labels/files cannot supersede it;
- each MIRROR gets independent mutable history, while immutable baked art/material can be cached/shared safely.

## 4. Crystala — checkpoints, real geometry, and remote durability

Crystala demonstrated:
- gameplay truth checkpoint before complex presentation helps isolate failures;
- Gold presentation should consume real world geometry/projectile truth;
- protected shared systems need explicit regressions;
- a large local-only B/C checkpoint was lost after sandbox/auth failure.

Later minimal-delta work also proved that if Gold/presentation is already correct, mechanic-only changes should leave those bytes untouched.

**Mirror application:**
- work in durable remote checkpoints during implementation;
- this preload itself is one portable remote commit;
- do not modify Gold merely because gameplay mapping changes;
- real projectiles/nodes are the presentation inputs.

## 5. Frost — wrong Gold and render-state leakage poison everything

Frost failures showed:
- correct mechanics + green gates can still fail visually;
- wrong/obsolete Gold reference invalidates the whole bridge;
- generic lines/rectangles are not a substitute for Gold materials;
- RNG at the wrong semantic moment is “deterministic” but still wrong;
- stale contact latches and wrong body carriers break motion;
- declared config without runtime behavior is fake completeness;
- stale PASS counts after edits are invalid evidence;
- render-state leakage can resize/flicker unrelated actors;
- raw hitch dt and stale movement history break authored motion.

**Mirror application:**
- exact Gold 12 hash before coding;
- fixed 1/120 Gold state;
- post-movement root/history sample;
- seeded gameplay RNG for node orientation;
- full canvas save/restore;
- rerun evidence on exact final SHA.

## 6. Magnet — the most important warning: source translation can still drift

Magnet owner rejection is the closest analogue to MIRROR.

The rejected bridge had many green gates but:
- reconstructed Gold was tested against itself instead of canonical HTML;
- source equations were fed the wrong Apex kinematic waveform;
- browser proof covered A1 but not the real A2 firearm path;
- rendering tests blessed a Gold-owned function, not the actual desired visible primitive;
- donor diagnostic line-grid was copied into the real arena instead of transferring the causal deformation idea;
- real bullets were much faster than donor bullets, making technically applied effects practically unreadable;
- a post-collision sidecar integrator caused physical sticking.

The correction succeeded only after testing direct canonical parity, real fast objects, actual render-stage provenance, correct input seam and normal post-contact liveness.

**Mirror application:**
- canonical HTML direct-execution parity is mandatory;
- A2 snap must live at Gold-equivalent post-movement seam;
- thin mirror capture must be swept against real high-speed Arsenal paths;
- actual projectile classes must be tested, not synthetic slow demo bullets;
- visual tests must inspect real pixels/frames at normal scale;
- no second physics/movement integrator;
- do not validate “MirrorGold function called”; validate the surface/image/peel/swap/node the owner sees.

## 7. Proven architecture pattern

Use:

`REAL GAMEPLAY TRUTH -> THIN SEMANTIC ADAPTER -> COHERENT GOLD ENGINE -> ISOLATED DRAW`

Not:

`REAL GAMEPLAY -> APPROXIMATE EFFECT A + PARTIAL GOLD B + GENERIC FALLBACK C`.

For Mirror, because some mechanics themselves are Gold-first, the Gold contract also supplies deterministic timeline/geometry constants to the gameplay runtime. That shared contract prevents gameplay/presentation timing duplication.

## 8. Evidence rule

Every final report must separate:
- automated correctness;
- canonical parity;
- real-browser evidence;
- owner visual/feel acceptance.

Never collapse those into “all tests green, therefore Gold matched.”
